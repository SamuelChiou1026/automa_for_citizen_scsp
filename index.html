理念

本方案採用瀏覽器外掛自動填單，保留既有 Google 表單作業習慣，並使用個人社宅雲帳號，避免共用帳密及責任不清。即使系統更新或人員異動，也可自行修改腳本或透過 AI 協助維護，降低對原開發者的依賴與後續維護負擔。

PRINCIPLE

工具原理

在「社宅雲」租借公共空間，每一筆都要登入、找場地、同意規約、填一整張表單再送出。十幾二十筆手動填，既耗時又容易填錯。這套工具把工作拆成兩步。

填單小幫手

HTML 填單工具

場地租借CSV編輯.html

在一個表格裡把要租的場地、日期、時段等資料一次填好，並幫你檢查有沒有填錯，最後存成 CSV 檔。

  • 雙擊即可開啟，不用安裝、不用連網
  • 自動檢查日期、信箱格式
  • 資料自動保存在瀏覽器
自動申請機器人

Automa 機器人

社宅場地租借.automa.json

讀取剛剛存好的 CSV 檔，自動登入社宅雲，一筆一筆幫你填表、送出申請，最後告訴你哪幾筆成功、哪幾筆失敗。

  • 自動登入台北通
  • 逐筆填表並送出
  • 產出成功／失敗清單
打開 HTML 填寫資料➜ 匯出 CSV 檔➜ 在 Automa 執行機器人➜ 自動登入並逐筆送出➜ 成功／失敗清單

簡單說：先用 HTML 填資料，再讓機器人幫你送出申請。

PREPARATION

事前準備

以下設定只需要做一次。

  • 電腦：Windows 或 Mac 都可以

    兩種系統都能使用，不需要額外安裝程式。

  • 瀏覽器：建議 Google Chrome

    Microsoft Edge 也可以。

  • 安裝 Automa 擴充功能

    到 Chrome 線上應用程式商店搜尋「Automa」並安裝。

  • 開啟檔案存取權限 很重要

    沒開的話，機器人會讀不到 CSV。

    1. 在網址列輸入 chrome://extensions 並按 Enter
    2. 找到 Automa，按「詳細資料」
    3. 打開「允許存取檔案網址」

  • 匯入機器人流程

    打開 Automa → 工作流程（Workflows）→ 匯入（Import）→ 選擇 社宅場地租借.automa.json。

  • 確認登入帳號

    機器人會用流程裡設定好的台北通帳號密碼登入。要改成自己的帳號，請在 Automa 打開流程，修改「輸入帳號」「輸入密碼」兩個方塊。

⚠ 帳密安全提醒

流程檔裡直接存有台北通帳號密碼，請勿把 社宅場地租借.automa.json 隨意轉傳給不相關的人，也不要上傳到公開網站。

FAQ

常見問題

方案設計說明

一為什麼不採用線上表單系統直接自動填單？

本方案不採用獨立的線上表單系統直接串接或自動操作社宅雲，主要考量在於系統穩定性、後續維護成本，以及帳號使用的責任歸屬。

社宅雲是由外部單位維運的平台，我們無法掌握其系統狀態與更新時程。若自動填單時遇到系統維護、服務異常、資料傳輸缺漏，或平台介面更新，都可能造成自動化流程失效，進而影響場地租借申請。

一旦發生問題，除了可能影響場地使用安排，也可能需要原系統開發者介入排查與修正，形成長期的維護負擔。

二避免共用帳號造成管理與責任問題

另一項重要考量，是不希望將社宅雲的帳號與密碼集中綁定於某一位青創成員，再由該帳號統一執行所有自動填單作業。

若該成員日後不再續租、退出團隊，或與團隊發生其他爭議，都可能影響系統的持續運作，也會衍生帳號交接、權限管理及責任歸屬等問題。

因此，本方案傾向讓每位成員使用自己的社宅雲帳號操作，避免共用帳密所帶來的管理風險，並由實際申請者確認申請內容及承擔相應責任。

三為什麼選擇瀏覽器外掛？

考量青創團隊目前已習慣透過 Google 表單提交場地租借需求，本方案不打算改變既有的填單流程，而是採用瀏覽器外掛搭配自動填單腳本，協助將 Google 表單中的資料帶入社宅雲。

這種做法有以下優點：

  • 保留原有作業習慣：成員仍透過熟悉的 Google 表單提交需求，不必重新學習一套申請系統。
  • 使用個人帳號：自動填單在成員自己的瀏覽器及社宅雲登入環境中執行，避免集中管理所有人的帳號與密碼。
  • 降低維護依賴：若社宅雲更新介面，導致腳本無法正常運作，可由具備相關能力的成員自行修改，也可將腳本交由 AI 協助分析與修正，不必每次都仰賴原開發者。
  • 降低人員異動的影響：即使原開發者或其他青創成員離開，只要腳本及操作文件有妥善保存，後續仍可由其他人接手維護。
四方案的核心原則

本方案並不是要打造一套需要長期仰賴特定開發者維護的新系統，而是以最小幅度的技術介入，解決現有作業中的重複填寫問題。

核心原則如下：

  1. 不改變既有流程：保留 Google 表單作為團隊內部的需求蒐集工具。
  2. 不集中管理帳密：每位成員使用自己的社宅雲帳號，避免共用帳號所造成的風險。
  3. 降低對原開發者的依賴：讓腳本具備可交接、可修改、可由其他人接手維護的特性。
  4. 申請者自行確認：自動填入資料不代表申請已成功，仍須由申請者確認資料正確、完成送出，並確認社宅雲實際受理結果。

操作問題

問機器人說「讀取檔案失敗」
檢查路徑有沒有打錯、檔名有沒有含 .csv，以及 Automa 是否已開啟「允許存取檔案網址」。
問機器人說「標題列缺少欄位」
請用 HTML 工具匯出的 CSV，不要用 Excel 另存造成格式跑掉。
問某筆顯示「送出後未確認成功，可能已送出」
網站反應較慢，請到社宅雲的「空間租借紀錄」確認是否已申請，避免重複送出。
問某筆顯示「沒有可選的租用時段」
該日期時段可能已被別人借走或尚未開放，請換日期或時段。
問HTML 打開後資料不見了
可能換了瀏覽器或清除了瀏覽紀錄。用「匯入 CSV」把之前匯出的檔案讀回來即可。
問想改信箱、日期後重跑失敗的幾筆
在 HTML 裡只保留失敗的那幾筆，修正後重新匯出，再執行一次機器人。
